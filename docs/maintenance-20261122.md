# 찜·제보 메모 안정화 (2026-11-22)

기준: 원격 main `56c5fa31bd859362011aba82abcc676c179dcd16`.

## 변경

- 찜 추가·해제는 기기 저장에 성공한 뒤 화면에 반영한다. 저장 실패 시 기존 상태를 유지하고 실패를 안내한다.
- 찜 목록에서 해제하면 카드·개수가 즉시 갱신된다. 마지막 찜을 해제해도 선택된 `찜 0` 필터를 유지해 전체 목록으로 돌아갈 수 있다.
- 잘못된 찜 저장값으로 앱이 멈추지 않는다. 다른 탭의 찜 변경·저장소 비우기도 반영하고, 검색 입력과 키보드 초점을 보존한다.
- 제보 메모의 제어문자를 먼저 정리한 후 이메일·전화번호를 제거한다. 기존 길이 제한·줄바꿈·시트 수식 방어는 유지한다.
- 캐시 버전 갱신 스크립트는 `fileURLToPath`로 경로를 처리해 Windows와 공백·한글·`#`가 있는 경로에서도 실행된다. 화면 모듈 버전과 서비스 워커 캐시를 함께 갱신했다.

## 검증

- 전체 테스트 456개 실행. 451개가 처음 실행에서 통과했다.
- 5개 실패는 작업본의 CRLF/LF 차이와 Windows의 `/tmp` 캡처 저장 경로 때문이었다. 원격 blob SHA와 대조해 작업본을 정규화하고, 로컬 테스트에서만 캡처 위치를 변경한 뒤 해당 파일 39개 테스트가 모두 통과했다. 이 재검증에는 새 캐시 경로 테스트 1개가 포함된다.
- 중복을 제외한 검증 항목은 총 457개다. 찜 브라우저 검증 16개, Apps Script v4/v5/v6 검증 19개, 캐시 경로 검증 1개를 포함한다.
- 브라우저 검증은 설치된 시스템 Chrome으로 수행했다. 저장소의 Playwright 의존성과 CI 실행 방식은 변경하지 않았다. 운영 데이터 대신 테스트 응답을 사용했다.

## 반영 시 확인

- 프런트엔드 변경은 작업 브랜치 병합·배포 후 사용자에게 반영된다.
- `apps-script/Code.gs` 변경은 Apps Script의 새 버전 배포가 별도로 필요하다. Git 커밋만으로 운영 백엔드가 바뀌지는 않는다.
- 이번 작업에서 광고 활성화, 도메인 설정, 운영 데이터 변경은 수행하지 않았다.
