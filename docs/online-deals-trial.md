# 온라인 특가 자동화 (2026-11-05)

기본 화면은 프랜차이즈 쿠폰 비교다. 온라인 특가는 마지막 메뉴에서 고른 경우에만 열린다. 쿠폰 수집기(`collect.yml`)·`coupons`·`news` 탭·추천 순위·통신사/결제수단 필터에는 온라인 상품을 섞지 않는다.

## 1. 실제 연결 상태

**연동 구조 구현 및 모의 검증 완료 / 실제 운영 연결 미완료.**

| 공급처 | 상태 | 이유 |
| --- | --- | --- |
| 쿠팡 파트너스 | 승인 대기 · 호출 코드 없음 | 계정 없음. 최종 승인 후 Open API 키를 받아야 하고, 호출 주소·응답 필드·호출 한도는 승인 후 문서로 확인한다. |
| 링크프라이스 | 승인 대기 · 호출 코드 없음 | 계정 없음. 핫딜·리얼핫딜 API는 제휴사 가입·사이트 등록·광고주 승인 후 이용 가능하며 API 문서가 공개돼 있지 않다. |

- 두 공급처 모두 `collector/src/online/suppliers.js`에서 `fetch: null`이다. 실행기는 호출하지 않고 '승인 대기 (연결 안 됨)'으로만 기록한다.
- 호출 주소·응답 필드를 추측해서 만들지 않았다. 커뮤니티 게시판 수집·로그인 영역·비공개 API·차단 우회는 쓰지 않는다.
- 공개 화면은 지금 '아직 자동으로 확인한 상품이 없어요.'와 쿠팡 골드박스 일반 링크(제휴 아님)만 보인다.
- 모든 상품 데이터 검증은 테스트 안의 가짜 공급처·가짜 네트워크로 했다. 실제 상품·가격을 받은 적은 없다.

## 2. 자동화 범위

```
3시간마다 (online-deals.yml, 관리 화면 '지금 다시 확인'도 가능)
  └ 실행기 collector/src/online/run.js
      ├ Apps Script online_run_start  ← 동시 실행 잠금(20분) + 규칙·공급처 모드
      ├ 공급처별로 따로: 끄기·승인 대기·키 없음·일시 중지·최소 간격 → 호출 안 함
      │   └ 어댑터 fetch (승인 후 구현) → 표준 후보 → odNormalize
      ├ Apps Script online_ingest     ← 같은 규칙으로 다시 정리·반영 (실패·빈 응답은 상품을 건드리지 않음)
      └ Apps Script online_run_finish ← online_runs 기록, 잠금 해제
공개 화면 → GET online_deals  ← 읽을 때마다 상태 다시 계산 (60초 캐시)
관리 화면 → online_admin / online_admin_set (ADMIN_TOKEN)
```

- 판단 규칙은 `collector/src/online-deals-core.js` 하나다. `npm run sync-web`이 화면(`web/online-deals-core.js`)과 Apps Script(`Code.gs` 생성 구역)에 같은 내용을 넣는다. 테스트가 세 사본이 같은지 확인한다.
- 호출 규칙(`collector/src/online/http.js`): 허용한 HTTPS 호스트만, 다른 주소로 넘어가는 응답 금지, 요청 간격, 10초 시간 제한, 응답 2MB 제한, 5xx·네트워크 오류만 최대 2회 재시도, 429는 Retry-After가 30초 이하면 기다리고 길면 공급처 일시 중지. 오류 기록에 주소의 쿼리·키·서명을 남기지 않는다.
- 새 공급처는 '관찰 (비공개)'로 시작한다. 받은 상품은 보류 목록에서만 보이고, 운영자가 '자동 게시'로 바꿔야 공개된다.

## 3. 게시·보류·종료 기준

**게시**: 아래 보류 사유가 하나도 없고, 공급처가 '자동 게시'이며, 기간 안이고, 같은 상품 중 가장 최근 확인한 것이며, 최대 게시 수(기본 30) 안일 때.

**보류 사유** (관리 화면에 한국어로 표시)

| 코드 | 기준 |
| --- | --- |
| `BAD_PRICE` · `BAD_CURRENCY` | 원화 양의 정수 가격이 아님 (1000만원 초과도 보류) |
| `PRICE_NOT_TOTAL` | 공급처가 상품 실구매가라고 표시하지 않음: 단위 가격·할인액·적립금·최소 주문금액·불명은 가격으로 쓰지 않음 |
| `OPTION_PRICE_UNCLEAR` | 옵션마다 가격이 다른데 옵션이 특정되지 않음, 또는 옵션 가격 여부 불명 |
| `PERSONAL_PRICE` | 첫 구매·개인 쿠폰 등 사람마다 다른 가격이거나, 그 여부를 모름 |
| `CONDITION_UNCLEAR` | 공급처가 조건이 완전하다고 하지 않음, 빈 조건, 300자 넘는 조건, 9개 이상 (조건은 자르거나 줄이지 않는다) |
| `BAD_LINK` | 공급처별 허용 HTTPS 호스트가 아님, 계정·포트·토큰·개인 쿠폰 정보가 든 링크 (링크프라이스는 링크 주소 확인 전이라 전부 보류) |
| `SELLER_UNKNOWN` | 판매자 불명 |
| `CATEGORY_UNMAPPED` · `CATEGORY_EXCLUDED` | 분류 규칙에 없거나 게시하지 않는 분류 (공급처 분류 경로의 한 단계와 정확히 같아야 연결 — '가전 > 냉동고'가 식품이 되지 않음) |
| `SELLER_EXCLUDED` · `KEYWORD_EXCLUDED` | 운영자가 제외한 판매자·키워드 (기본: 주류·담배·전자담배·의약품·성인용품) |
| `DUPLICATE` · `OVER_LIMIT` | 같은 상품(상품명·옵션·판매처)이 이미 게시 중 / 최대 게시 수 밖 |
| `SUPPLIER_OBSERVE` · `SUPPLIER_OFF` | 공급처가 관찰 모드 또는 꺼짐 |

**기간 (두 가지를 따로 저장·표시)**
- 실제 행사 종료(`endsAt`): 공급처가 준 값만. 지나면 '종료'.
- AMONG 재확인 기한: 마지막으로 받은 시각 + 6시간(관리 화면에서 1~24시간). 지나면 '재확인 기한 지남'으로 공개 목록에서 빠진다. 공개 목록은 둘 중 이른 시각까지만 보인다.
- 공급처가 품절·종료라고 하면 '종료'. 시작 전이면 '시작 전'.

**지우지 않는 경우**
- 실패·빈 응답·전부 형식 오류인 응답은 기존 상품을 그대로 둔다. 이번 응답에 없는 상품도 품절로 보지 않는다(다시 받지 못하면 재확인 기한이 지나 자동으로 내려감).
- 운영자 숨김은 다시 받아도 유지되고 보관 정리에서도 남는다.
- 7일간 다시 받지 못한 상품 기록만 정리한다(최대 2000개). 가격 이력은 저장하지 않는다.

**화면 표시**: 확인 당시 가격(쉼표 없이 `7900원`), 옵션·판매자, 배송비(`무료배송` / `배송비 3000원` / `19800원 이상 구매 시 무료배송` / 모르면 `배송비 확인 필요` — 무료로 쓰지 않음), 회원 가격·조건 전체, 확인 시각, 실제 행사 종료. 최저가·할인율 표현은 만들지 않는다. 사진은 공급처별 이용 범위를 확인하기 전에는 표시하지 않는다(`imagesAllowed: false`).

**제휴 고지**: 제휴 상품이 하나라도 있으면 목록 위에 공급처 문구를 먼저 보여 준다. 쿠팡은 공식 가이드의 필수 문구 '이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.' 상품마다 '제휴광고'와 `rel="sponsored noopener noreferrer"`. 화면은 서버 문구를 그대로 쓰지 않고 자기 목록으로 고지를 정한다.

## 4. 운영자 역할 (관리 화면 `admin.html` → 온라인 특가 자동화)

상품을 직접 입력하지 않는다. 운영자는 예외와 규칙만 다룬다.

- 공급처: 연결 상태(승인 대기·키 미등록·연결됨·실패·호출 제한), 모드(끄기 / 관찰 / 자동 게시), 일시 중지 해제.
- 보류 목록 확인: 사유를 보고 규칙을 고치거나(분류 연결 단어 추가 등) 그대로 둔다.
- 숨김: 게시 중이라도 이상하면 숨긴다(사유 선택 입력). 다시 받아도 숨김 유지, '숨김 해제'로 되돌림.
- 분류 지정: 상품별로 식품·생활용품·게시 안 함을 기한과 함께 지정(기한이 지나면 규칙으로 돌아감).
- 규칙: 게시 분류, 분류 연결 단어, 제외 키워드·판매자, 최대 게시 수, 재확인 기한.
- 지금 다시 확인: `online-deals.yml` 실행(10분 재요청 제한).

## 6. 공급처를 실제로 연결할 때 (대표 승인 필요)

**쿠팡 파트너스**
1. 파트너스 가입·약관 동의·활동 매체 등록(AMONG 사이트·온라인 특가 페이지). 제휴 링크를 싣는 모든 페이지를 등록해야 한다.
2. 최종 승인 (공식 가이드 기준 누적 판매 15만원 이상부터 심사). 승인 전에는 Open API를 쓸 수 없다.
3. Open API 키 발급 → GitHub 저장소 Settings → Secrets and variables → Actions에서 `COUPANG_PARTNERS_ACCESS_KEY`, `COUPANG_PARTNERS_SECRET_KEY`로 대표가 직접 등록.
4. 승인 후 받은 공식 문서로 호출 주소·응답 필드·호출 한도·사진/캐시 이용 범위를 확인 → `suppliers.js`에 `apiHosts`·`fetch`(필드 → 표준 후보), 확인되면 `imagesAllowed`를 바꾼다. 문서에 없는 값은 비워 둔다(예: 배송비를 모르면 `unknown`).
5. 관찰 모드로 하루 이상 돌려 보류 사유를 확인한 뒤 '자동 게시'로 바꾼다.

**링크프라이스**
1. 제휴사(퍼블리셔) 가입·사이트 등록, 핫딜/리얼핫딜 API 이용 신청과 광고주별 제휴 승인.
2. 승인 후 받은 문서로 호출 주소·필드·한도, 제휴 링크 호스트(`OD_SUPPLIERS.linkprice.linkHosts`), 사진 이용 범위를 확인해 어댑터를 만든다. 고지 문구도 링크프라이스 정책에 맞는지 확인한다.

## 7. 남은 한계

- 실제 공급처 응답으로 검증하지 않았다. 필드 대응·호출 한도·인증 방식은 승인 후 문서로 다시 확인해야 한다.
- 링크프라이스 링크 호스트가 비어 있어 연결해도 모든 상품이 `BAD_LINK`로 보류된다(확인 후 추가).
- 공개 목록 캐시가 60초라 기한이 지난 상품이 최대 1분 남을 수 있다(화면이 다시 검사해 숨김).
- GitHub 예약 실행은 수 분~수십 분 늦을 수 있고, 공개 저장소에 60일간 커밋이 없으면 멈춘다.
- 시트 저장이라 상품 수가 수천 개로 늘면 느려질 수 있다(보관 2000개 상한).
