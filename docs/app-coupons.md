# 앱 전용 쿠폰 운영

공개 화면: `/?view=appCoupons`. 관리 화면: `/admin.html`의 **앱 전용 쿠폰 관리**.
기존 `ADMIN_TOKEN` 인증을 그대로 사용한다. 공개 API에는 초안과 운영 메모가 포함되지 않는다.
개인 계정 세션, 기기 화면, 알림, 접근성 수집은 사용하지 않는다.

## 등록과 확인

1. 발급 앱과 실제 사용 브랜드, 상품·구성, 혜택 방식과 금액, 쿠폰별 대상·등급 근거를 입력한다.
2. 발급/사용 기간을 **Asia/Seoul** 기준으로 각각 입력한다. 종료 입력 분은 마지막 밀리초까지 포함한다. 상대 유효기간 쿠폰은 해당 쿠폰의 실제 사용 종료일을 확인해야 공개할 수 있다.
3. 조건별로 **미확인 / 확인됨 / 해당 없음**을 구분한다. 제외 매장·유의사항은 축약으로 누락하지 않는다. 긴 입력은 오류를 표시하며 조용히 잘라 저장하지 않는다.
4. 공식 출처와 이용 링크는 별도다. 행사·앱·설치 안내 중 실제 목적지를 선택한다. 설치 안내는 확인한 앱 내 경로가 필요하다. 비공개 사용 코드·토큰·세션 주소는 등록하지 않는다.
5. 출처 이용 조건을 확인한 근거를 기록한다. 불명확하면 초안에 남긴다. 배너·앱 화면 전체를 복제하지 않는다.
6. 실제 조건 확인 후 **쿠폰의 대상·혜택·기간·조건을 실제로 확인했음**을 체크한다. 과거 확인일은 별도로 입력할 수 있다. 링크 접속 확인 체크는 이 기록과 별개다.
7. 초안 저장 또는 검증 후 공개한다. 필수 사실이 없으면 서버가 공개를 거부한다. 공개된 조건을 바꾸면 재확인 후 공개하거나 초안으로 저장한다.

목록 조회, 페이지 새로고침, 배포, 조기 마감은 `checked_at`을 갱신하지 않는다. 링크가 열려도 발급 가능 여부는 별도로 확인해야 한다. 48시간 이상 된 기록은 관리자 재확인 목록과 공개 재확인 표시가 붙고 핫딜에서 제외된다.

## 상태와 핫딜

- 발급 마감 이후: 새 발급 목록/핫딜에서 제외, 사용 기한이 남으면 받은 쿠폰 목록에 유지.
- 사용 종료 이후: 공개 진행 중 목록/핫딜에서 제외. 원본은 관리자에서 유지한다.
- 조기 마감: 발급과 사용을 각각 처리한다. 마감 취소는 실제 재확인이 필요하다.
- 같은 `app_coupons` 행을 두 화면이 참조한다. 별도 핫딜 행을 생성하지 않는다.
- 해피포인트 핫딜은 1+1 또는 즉시 할인 50% 이상. 앱쿠폰 목록에는 이 기준을 적용하지 않는다. 다른 앱 핫딜은 1+1 또는 공식 할인율 30% 이상을 후보로 삼는다. 포인트 환급/교환을 즉시 할인으로 계산하지 않는다. 반복 행사는 후순위다.
- 동일 행사 링크 또는 겹치는 사용 기간의 동일 상품은 중복 후보를 표시한다. 다른 쿠폰이라면 이유를 기록해야 공개된다. 과거 수집 기록은 `coupon:ID` / `news:ID`를 연결해 중복 노출을 막는다. 연결한 기록은 관리 쿠폰 종료 후에도 다시 노출하지 않는다.
- 공개 페이지는 매초 기한을 계산하고, 화면이 활성화될 때와 매 60초마다 운영 변경을 읽는다. 오프라인 상태에서는 조기 마감 정보를 받을 수 없으므로 공식 발급처에서 최종 확인한다.

## 저장과 배포

새 `app_coupons` 탭에 인덱스 열과 정규화한 JSON payload를 저장한다. 스키마 v6 마이그레이션은 기존 데이터/열을 보존하며 조사 초안 3개를 한 번만 추가한다. 민감한 메모는 공개 API에서 제외한다. 동시 수정은 revision 충돌로 거부한다.

규칙 원본: `collector/src/app-coupons.js`. 백엔드 원본: `apps-script/app-coupon-backend.gs`.
수정 후 `node collector/scripts/sync-web.js`를 실행한다. 웹 사본과 **Code.gs 하단 생성 구역**이 갱신된다.
Apps Script에는 생성된 **Code.gs 한 파일만** 적용한다. `app-coupon-backend.gs`를 별도 파일로 추가하면 중복 선언되므로 추가하지 않는다.
기존 Apps Script 웹앱 배포를 새 버전으로 갱신해 URL을 유지한다. 프런트는 기존 GitHub Pages workflow로 배포한다.

API: 공개 GET `app_coupons` 및 기존 GET `coupons`의 `app_coupons` 필드. 관리자 POST `app_coupon_list`, `app_coupon_save`, `app_coupon_close`, `app_coupon_duplicates`는 모두 ADMIN_TOKEN을 요구한다.

## 2026-10-29 조사 초안

실제 공개 가능한 조건 전체를 확인한 쿠폰은 아직 없다. 샘플은 공개하지 않는다.

- 버거킹 등급별 쿠폰: 공식 공지 `https://www.burgerking.co.kr/notice/90`. 개별 상품·가격·등급·기간·주문 조건 확인 필요.
- 맥도날드 포인트 교환 쿠폰: 공식 약관 `https://m.mcdonalds.co.kr/gmal/kor/more/tnc/tnc_202512.html`. 상품·포인트·대상·기간·이용 링크 확인 필요. 일반 쿠폰을 전체 회원으로 확정하지 않음.
- 해피포인트 쉑버거 1+1: 사용자가 제공한 공식 공유 링크의 제목 메타데이터만 확인. 전체 회원 대상·발급/사용 기간 구분·선착순 조건·제외 매장 확인 필요. 날짜 제목을 사용 기간으로 추정하지 않음.

세 자료 모두 자료 게시 범위도 추가 확인해야 한다. `researched_at`은 조사일 메타데이터이며, 핵심 쿠폰 조건을 확인하지 않아 `checked_at`은 비워 둔다.
